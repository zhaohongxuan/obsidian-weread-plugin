# 划线收藏：3.1.0 Canvas 实施方案

状态：按用户最新要求，以原生 `.canvas` 作为主存储；保留插件列表/卡片视图，移除导出功能。基于 3.0.0，更新 PR #498，版本保持 3.1.0。

## 使用方式

- 今日、回顾、那年今日和旧句重逢中的个人划线支持星标收藏。
- 收藏 Tab 保留搜索、排序、列表/卡片切换、分批加载、取消和限时撤销。
- 通过「在Canvas中打开」或命令「打开微信读书收藏画布」直接打开同一份收藏文件，不另建导出副本。
- 空收藏也可以打开画布；首次主动打开时创建有效的空收藏画布。
- 收藏归属当前笔记库，退出登录、换 Key 或清理笔记缓存均不会清除收藏。不存认证信息，也不修改原书籍 Markdown。

## 主数据与文件

```text
WereadData/favorites/
  favorites.canvas                 # 主数据，也是 Obsidian 原生画布
  favorites.canvas.previous.json   # 上一个有效 Canvas 文档备份
  favorites.canvas.staging.json    # 写入校验用暂存 Canvas 文档
  favorites.corrupt.<unique>.json  # 恢复前保留的原始损坏内容
  favorites.json                   # 旧主库，迁移后原样保留
  favorites.previous.json          # 旧备份，原样保留
```

备份和暂存文件内容仍是 Canvas JSON，扩展名用于避免与主画布混淆。收藏页不再提供导出按钮，也不生成收藏导出文件。

原生格式遵循 [JSON Canvas 1.0](https://jsoncanvas.org/spec/1.0/)。顶层 `nodes`、`edges` 可省略并按空数组处理；存在时必须是数组。卡片、分组和连线使用标准类型与字段。

## 元数据与原生编辑

不依赖 Obsidian 可能丢弃的自定义顶层/节点字段。收藏元数据保存在标准文本节点的 Markdown HTML 注释中，使用 URI 编码 JSON，避免正文或书名中的 `-->` 破坏注释。原生浏览中显示正文、书籍与来源，注释不作为可见正文展示。

- 每条收藏对应一个文本节点；隐藏元数据保留原始 JournalNote.id、来源、书籍、收藏时间和划线时间。
- 有安全 HTTP(S) 封面地址时，在卡片顶部生成宽度 80 的原生 Markdown 图片；地址含凭据或协议不安全时不渲染。封面由独立生成区块和严格的 `cover: true` 标识描述，不属于句子正文，也不污染复制、搜索或重新保存的快照。
- 打开旧画布前先保存并重读原生编辑，再按需补齐缺失封面。已有坐标、尺寸、颜色、手动来源尾注和自定义图片宽度保持不变；再次打开不重复插图或改写文件。新卡片默认高度 400，现有卡片不强制扩高。远程封面依赖图片链接可访问，正文仍可离线阅读。
- 独立的「我的收藏」说明节点保存内部 schema、版本与插件取消操作产生的墓碑。
- 正文与生成的来源尾注有独立分隔。原生编辑正文后，插件读取编辑后的句子；来源信息继续用于跳转和去重。
- 保存其他收藏时，保留原卡片的坐标、尺寸、颜色及其他节点属性，不重新排列用户布局。
- 用户添加的自由文本、文件、链接、分组、连线及未知扩展字段原样保留；自由卡片不自动当作有微信读书来源的收藏。
- 在原生 Canvas 中删除收藏卡片后，插件取消该来源的星标，不从旧 JSON 或过期元数据中复活卡片。
- 插件取消收藏时，仅移除相应卡片及其关联连线，保留其他内容；撤销恢复快照。
- 删除说明节点不丢失剩余收藏；下次插件保存时重建说明节点。有效空 Canvas 保持为空，不从旧 JSON 重新导入。
- 可解析但结构不支持的 Canvas、已识别的收藏元数据损坏、重复来源或未来 schema 进入只读保护，不擅自覆盖；只有 JSON 语法损坏或截断才可走备份恢复。原生编辑应保留收藏注释，不将复制/删改内部元数据当作普通正文操作。

正文初次收藏时保存快照，远端划线变化不会自动覆盖。用户在 Canvas 中主动改正文属于本地收藏编辑，不回写微信读书或原书籍笔记。

## 旧 JSON 迁移

1. 仅在 Canvas 主文件、Canvas 备份和暂存均不存在时检查旧 JSON。
2. 校验旧 schema、来源 ID、记录与时间，生成带标准文本卡片的新 Canvas。
3. 写入后读回验证，再将新文件作为主库；旧 JSON 及其备份均保持字节不变。
4. 如果旧主文件损坏但旧备份有效，从旧备份转换，同时保留损坏原件。旧格式来自未来版本或无可用备份时停止写入。
5. 已有 Canvas 优先，包括空 Canvas；不会用旧 JSON 覆盖用户原生整理、删除后的状态。

## 写入、恢复与实时刷新

- 单例收藏服务统一串行修改；保存前先完成加载，返回的记录与订阅状态为副本。
- 每次写前检查磁盘基线，生成暂存文档并读回验证，备份有效前驱，再次检查基线，写主文件并读回验证；成功后才更新星标。
- 主画布经 Vault.create / Vault.modify 写入，新文件立即进入 Obsidian 文件索引，打开的 Canvas 能收到标准修改通知。目录使用 Vault.createFolder。
- 写入前先校验磁盘基线，再通过 TextFileView.save 仅保存同路径的已打开 Canvas 草稿，并在原队列中重读后合并；不触碰其他笔记，已有外部更新时不先保存陈旧草稿。
- 监听原生主画布的 create / modify 事件，短暂合并事件后将强制重读排入同一队列；忽略服务自身写入事件，避免重读回环。进入收藏面板和错误重试也强制重读。
- 主画布或其上级目录被删除、移走或改名时立即停止写入，再排队重读。已知主文件缺失或仍存在 Canvas 备份/暂存时保持只读，不自动恢复旧备份或重新迁移旧 JSON；用户将有效画布恢复到原路径后可重新读取并继续使用。
- 强制重读等待已接受写入与初始加载，避免修改 Repository 的基线时打断提交。
- 普通损坏或截断先保留原始字节，再从有效备份恢复；未来格式或已识别元数据损坏不以旧备份覆盖。恢复失败时只读。
- 卸载时释放文件事件、计时器与界面订阅；已接受的写入按原队列完成。

多设备同时离线写入仍不提供自动合并保证。现有同步工具可以同步原生 `.canvas` 文件，但写前校验不是跨设备锁或 compare-and-swap。

## 验证

- 格式：标准 JSON Canvas、可省略数组、元数据注释、文字与 HTML 结束符、尾注分隔及重复来源保护。
- 原生状态：移动、缩放、颜色、手动节点/分组/连线和扩展属性；编辑正文、删除卡片与删除说明节点。
- 迁移：旧 JSON 正常/损坏/未来版本；原文件字节保留；已有空 Canvas 不重新导入。
- 持久化：重启、取消/恢复、暂存和主文件部分写入、备份恢复、外部改动、队列与关闭。
- 真实临时文件系统：Vault 索引、原生修改事件到星标/列表、布局保留及旧书籍文件保护。
- 生产 UI：打开真实主路径的新 Canvas 标签页、空收藏、只读/失败提示、关闭时防止迟到打开、原有双视图和星标功能。
- 本机安装：五个插件 Tab 与原生收藏 Canvas 的打开命令；自动化不向用户收藏注入测试句子。

## 模块

- `src/favoritesCanvas.ts`：Canvas 与收藏记录编解码、元数据、布局与连线保留。
- `src/favoritesRepository.ts`：验证写入、备份恢复、JSON 迁移、外部基线检查。
- `src/favorites.ts`：共享状态、串行操作、Canvas 文件索引与事件刷新。
- `src/components/wereadFavorites.ts` / `main.ts`：原生打开入口及生命周期保护。

后续范围：可靠多端操作合并、标签、自由卡片转换为独立本地收藏。当前没有导出功能或双主库同步。
